# PasswordVault v0.1.0

## 繁體中文

PasswordVault 是從 [FileLocker](https://github.com/lx-kvn/FileLocker) 的密碼庫（Password Locker）功能獨立出來的密碼管理應用程式，這是第一個正式版本。

### 亮點

- **獨立的密碼管理應用程式**：核心邏輯（`PasswordVault.Core`）與桌面應用程式（`PasswordVault.exe`，含內建 CLI）不依賴 FileLocker 本體即可單獨安裝執行；用 `git filter-repo` 完整保留原始碼與 commit 歷史，`git blame` 查得到功能當初在 FileLocker repo 裡的開發脈絡。
- **完整密碼庫管理功能**：帳密清單依分類分組並各自排序、搜尋（含加密備註欄位的解密比對）、新增／編輯／刪除（含批次刪除與最終確認）、密碼強度估計與重複使用提示、CSV 匯出入（相容自己的格式與 Chrome／Edge 匯出格式）。
- **TOTP 動態驗證碼**：新增／編輯表單支援掃描 QR 或手動輸入金鑰，即時預覽驗證碼；查看動態碼比一般密碼欄位更嚴格，有獨立的 30 秒新鮮度視窗，即使既有驗證階段仍有效也強制重新驗證一次。
- **瀏覽器擴充功能自動填入**：偵測登入／註冊表單自動填入、從密碼庫挑一筆既有帳密重複使用、註冊表單建議高強度密碼、送出表單後主動詢問是否儲存或覆蓋既有帳密，並支援網頁上的 TOTP 輸入框自動偵測與填入。
- **三種互相獨立的解鎖方式**：密碼、Passkey（改用標準 WebAuthn，不是 Windows 專屬的 `KeyCredentialManager`，見雲端同步規劃的多裝置考量）、恢復金鑰——跟 FileLocker 主體加密功能用的憑證完全分開。
- **內建 CLI**：`--list`／`--get` 兩個查詢指令，安全考量上限定只能互動式輸入主密碼，不提供具名參數或環境變數傳密碼的方式，因此不支援無人值守的自動化查詢——這是刻意的安全性取捨。
- **免提權安裝程式**：`no_admin_install` 模式打包，裝到 `%LOCALAPPDATA%\Programs\PasswordVault\`，不需要系統管理員權限、不彈 UAC。
- **與 FileLocker.App 共存時資料與轉接程式互相共用**：兩邊指向同一份密碼庫資料（`%LocalAppData%\PasswordVault\PasswordLocker\`），舊版使用者資料自動遷移（複製、不刪舊檔）；瀏覽器擴充功能的 Native Messaging Host 轉接程式也改成兩邊共用同一個實體檔案，修正過去兩邊各自帶一份副本時登錄檔／Named Pipe 兩套「贏家」判斷邏輯不一致造成的「Pipe is broken」連線失敗。
- **測試覆蓋**：`PasswordVault.Core.Tests`（146 個）、`PasswordVault.App.Tests`（8 個，移植自 FileLocker 的 Pipe Server 資安回歸測試）、`PasswordVault.Cli.Tests`（5 個），共 159 個測試全數通過。

### 已知限制

- **PasswordVault 自己的 Native Messaging Host 登錄機制還沒實作**：目前只有 `FileLocker.App` 那一側會寫登錄檔／manifest，只裝 `PasswordVault.exe`、不裝 `FileLocker.App` 的使用者，瀏覽器擴充功能實際上連不上任何東西。
- **這個 repo 的 Release 打包流程還沒能產出符合資產命名規則的相容性 zip**：`FileLocker.App` 消費 `PasswordVault.Core.dll` 的程式碼層級切換已經完成，但這邊還沒打包出正式給它下載的 Release 資產，這條路徑目前只驗證到程式碼層級，還沒有機會人工實測。
- **PasswordVault.exe 內建密碼庫引擎，沒有「部件未安裝」這個狀態**：共用套件裡「解除安裝密碼庫部件」這個按鈕在 PasswordVault.exe 上語意不適用，目前會顯示不夠精確的失敗提示，根治要回頭改共用套件加上參數隱藏這塊 UI，留到之後處理。
- **沒有數位簽章**：安裝檔執行時 Windows SmartScreen 可能會跳出警告。
- **雲端同步、網頁版金庫皆尚未實作**：架構與參數已完成兩輪 grilling 定案（見 `docs/specs/features/雲端同步_功能規劃.md`），但這輪只發布本機、零網路的密碼庫功能，雲端同步留待未來版本。
- 主密碼遺失無法復原，沒有任何後門機制——請務必妥善保存主密碼、Passkey 裝置與恢復金鑰。

## English

PasswordVault is a standalone password manager spun out of [FileLocker](https://github.com/lx-kvn/FileLocker)'s Password Locker feature. This is the first official release.

### Highlights

- **A standalone password manager**: the core logic (`PasswordVault.Core`) and desktop app (`PasswordVault.exe`, with a built-in CLI) install and run independently of FileLocker. The source code and full commit history were migrated with `git filter-repo`, so `git blame` still traces back to how each feature was originally developed in the FileLocker repo.
- **Full credential management**: entries grouped by category with their own sort order, search (including decrypted matching against encrypted notes), add/edit/delete (with batch delete and a final confirmation), password strength estimation and reuse warnings, and CSV import/export (compatible with its own format as well as Chrome/Edge exports).
- **TOTP codes**: the add/edit form supports scanning a QR code or entering a secret manually, with a live code preview. Viewing a code is stricter than a regular password field — it has its own 30-second freshness window and forces re-verification even if an existing verification session is still valid.
- **Browser extension autofill**: detects login/signup forms and autofills them, lets you reuse an existing credential, suggests a strong password on signup forms, offers to save or overwrite a credential after form submission, and autodetects/fills TOTP input fields on websites.
- **Three independent unlock methods**: password, passkey (now standard WebAuthn instead of the Windows-only `KeyCredentialManager`, to support multiple platforms — see the cloud sync planning doc), and a recovery key — a completely separate credential set from FileLocker's own encryption feature.
- **Built-in CLI**: `--list`/`--get` for querying credentials. For security, it only accepts the master password interactively — no named parameter or environment variable for passing it — so it doesn't support unattended automation. This is a deliberate trade-off.
- **No-admin installer**: packaged in `no_admin_install` mode, installing to `%LOCALAPPDATA%\Programs\PasswordVault\` with no administrator privileges or UAC prompt required.
- **Shared data and native-host relay when running alongside FileLocker.App**: both apps now point at the same credential data folder (`%LocalAppData%\PasswordVault\PasswordLocker\`), with legacy data auto-migrated (copied, old files kept). The browser extension's Native Messaging Host relay is likewise a single shared binary for both apps, fixing a "Pipe is broken" connection failure that used to occur when each app carried its own copy and the registry (last-launched wins) and the named pipe (first-launched wins) disagreed on which copy was authoritative.
- **Test coverage**: `PasswordVault.Core.Tests` (146), `PasswordVault.App.Tests` (8, ported from FileLocker's Pipe Server security regression tests), and `PasswordVault.Cli.Tests` (5) — 159 tests total, all passing.

### Known limitations

- **PasswordVault's own Native Messaging Host registration isn't implemented yet**: only `FileLocker.App` writes the registry/manifest entry, so users who install only `PasswordVault.exe` (without `FileLocker.App`) currently can't connect the browser extension to anything.
- **This repo's Release packaging pipeline can't yet produce a zip matching the asset naming convention**: `FileLocker.App`'s code-level switch to consuming `PasswordVault.Core.dll` is done, but this repo hasn't yet packaged the actual Release asset for it to download — that path has only been verified at the code level, not manually tested end to end.
- **`PasswordVault.exe` has a built-in credential engine, so there's no "component not installed" state**: the shared package's "uninstall Password Locker component" button doesn't quite apply here and currently shows an imprecise failure message; a proper fix means adding a prop to the shared package to hide that UI, deferred for now.
- **No code signing**: Windows SmartScreen may warn when running the installer.
- **Cloud sync and a web-based vault aren't implemented yet**: the architecture and parameters went through two rounds of design review (see `docs/specs/features/雲端同步_功能規劃.md`), but this release only ships the local, zero-network credential manager — cloud sync is planned for a future version.
- A lost master password cannot be recovered — there is no backdoor. Keep your master password, passkey device, and recovery key safe.
